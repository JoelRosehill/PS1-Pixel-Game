# Project Chromatic Odyssey — Build Roadmap

The game is built in **jobs**. Each job is one focused work session that ends in
something runnable. Later jobs build on earlier ones. Every job is checked
against the 5 pillars in [GDD.md](GDD.md).

**Stack:** TypeScript + Three.js (WebGL2), bundled with Vite. It runs in any modern
browser. Terrain, vegetation and core structures are procedural; selected hero
pieces use optimized GLB assets generated by the Blender pipeline.

**Camera:** the game became **first-person** after Job 4 (a kinetic movement pass added
wall-running, air slams and slam rebounds; see `npm run kinetictest`). Job notes below
that mention a chase camera or third person describe the state at the time.

## Job 2 — Player Movement ✅
- [x] **Custom kinematic controller** instead of Rapier — see the note below
- [x] Collision world: analytic terrain + oriented boxes / cylinders / spheres in a
      grid broadphase (~3,200 colliders, including every tree trunk)
- [x] Third-person camera: over-the-shoulder, boom shortens around geometry,
      FOV widens with speed, screen-shake hook ready for combat
- [x] Run / jump (coyote time, input buffer, variable height) / Quake-style air control
- [x] **Physics ground slide:** low friction, accelerates downhill, slide-jump keeps momentum
- [x] **Wall-slide & wall-jump** with a stick window and re-attach lockout
- [x] **8-way dash:** 3 charges, i-frames, air dashes, refills over time
- [x] Swimming (buoyancy) so deep water is not an invisible wall
- [x] Blocky knight, procedurally animated from movement state (no clips)
- [x] "The Wayfarer's Trial" course: slide ramp, low tunnel, wall-jump shaft,
      stepped platforms, dash gap, floating Lost Page
- [x] `npm run movetest`: 11 headless movement assertions

**Why not Rapier:** arcade movement wants exact control over slides and wall-jumps
rather than a generic solver; the terrain is an analytic height function, so ground
contact is exact and free with no trimesh baking (which matters once Job 6 streams
chunks); and it keeps the project dependency-free. Props are simple shapes, so
primitives are enough.

**Tuning:** all constants live in `PLAYER_TUNING` at the top of
`src/player/PlayerController.ts`. Change a number, run `npm run movetest`.

**Notes for Job 3:**
- `PlayerController.events` (jumped / walljumped / dashed / slid / landed) is set for one
  fixed step — hang VFX, audio and Momentum gains off it.
- `ThirdPersonCamera.addShake(amount)` exists and decays; hit-stop still needs doing.
- `controller.invulnerable` is true during a dash (i-frames for perfect-dodge rewards).
- The model's `armR` and `sword` groups are where attack animation should hook in;
  poses blend by state in `PlayerModel.update`.
- `ColliderWorld.deepestContact` / `sweepSphere` are reusable for hitboxes and projectiles.

## Job 3 — Spellblade Combat Core ✅
- [x] Combat core: `CombatWorld` target registry with swept-blade queries and aim assist
- [x] **Contextual attack set:** 3-hit light chain (slash → backhand → spin), chargeable
      heavy overhead, dash-thrust, slide-sweep, airborne plunge with an impact shockwave
- [x] Analytic blade arcs for hit detection, so hitboxes never depend on animation or framerate
- [x] **Hit-stop, screen shake, knockback and stagger**; dash/jump cancel attack recovery
- [x] **Parry** (tap Q) with a 0.18 s window → staggers the attacker, opens a 1.5 s
      riposte (34 dmg thrust); holding Q guards for 65% reduction
- [x] **Perfect dodge:** dash i-frames convert an incoming hit into Momentum + slow motion
- [x] **Momentum Pool** (no mana): +8 hit, +12 heavy, +15 dodge, +25 parry; drains after
      2.5 s idle; fills to *Resonance*, which halves spell cost until it falls below 35
- [x] **Rune Burst** (E, 40 Momentum): radial shockwave — the seed of Job 4's casting
- [x] Player HP, death and respawn at the Ember Shrine
- [x] **Sparring constructs:** stone golems with glowing seams that telegraph, swing,
      stagger, die and rebuild; plus passive dummies. Training yard south-east of the plaza
- [x] Effects pool: sword trails, impact sparks, shock rings, floating pixel damage numbers
- [x] Game HUD: Vigour, Momentum (gold in Resonance), dash pips, hit flash, death banner
- [x] `npm run combattest`: 11 headless combat assertions

**Two real bugs this job caught**
- Restoring the controller's contact list with `.length = n` could *grow* the array with
  holes, so the next step read `undefined.normal` and the game loop died. It now restores by copy.
- Edge-triggered input was cleared every frame, but hit-stop nearly freezes the fixed
  clock — so combo clicks pressed during hit-stop were swallowed. `Input.endFrame` now
  only consumes edges when a fixed step actually ran.

**Notes for Job 4:**
- `PlayerCombat.runeBurst()` is the template for a spell: cost → `momentum.spend` →

- `Effects` already pools sparks, rings, trails and numbers; add spell VFX there.
- The spellbook model should hang off `PlayerModel` next to `swordBack`/`swordHand`,
  which already swap the sword between back and fist.
- `ATTACKS` and `COMBAT_TUNING` in `PlayerCombat.ts` hold every combat number.
- The floating Lost Page on the trial course is the pickup to make real.

## Job 3.5 — Asset Pipeline & Hero Models ✅

The user dropped 40 PS1/low-poly packs into `assets/*.zip` (dragon, shadow demon, castles,
church, graveyard kit, swords, monsters, trees). Decision taken 2026-09-24:

- **Hero pieces only.** Terrain, trees, buildings and the player stay procedural (data-driven,
  streams well for the 40 biomes). Downloaded models are for showpieces: the red dragon boss,
  the shadow demon, the player's sword, church/graveyard set pieces.
- **Do this before Job 4** (the spellbook), so later jobs build on real assets.

The user expanded this job to **convert all 40 packs with Blender**, including Blend
sources, while retaining selected hero pieces in the playable level.

- [x] Recursively unpack ZIP/RAR sources without modifying original downloads
- [x] Blender 5.2 batch conversion: FBX, OBJ, Blend and glTF → self-contained GLB
- [x] Polygon reduction, coincident-vertex cleanup, static environment merging,
      ≤256 px embedded colour/emission textures, simplified materials
- [x] Preserve available rigs and animation clips; independent skeletons per instance
- [x] All 40 packs converted: about 1.65M → 193K triangles, 20.02 MiB total library
- [x] Cached `ModelLibrary`, toon materials, pixel texture filtering and auto-scaling
- [x] Imported player sword; chapel, eight graveyard pieces, demon display and animated
      dragon display in the proving grounds. Creatures do not have boss/enemy AI yet.
- [x] Runtime manifest, per-source hashes, optimization/validation report and credits inventory
- [x] `npm run assettest`: loads every GLB, checks clones and animations, captures previews

See [assets/PIPELINE.md](assets/PIPELINE.md) for commands and limitations and
[assets/CONVERSION.md](assets/CONVERSION.md) for per-pack results. Castle XIII and
The Lost Relic retain more than the 24K target to preserve disconnected details;
all other outputs meet their target. No licence notices were found in the archives;
the provenance inventory records that uncertainty rather than inventing attribution.

**Notes for Job 4:** `Game.assetsReady` resolves after hero assets finish loading;
screenshots await it. ModelLibrary owns shared resources; instances own their transforms
and bones. The imported sword still uses the original grip/back anchors and analytic
hitboxes. The procedural player and its future book are unchanged.

## Job 5 — Enemy Ecology I ✅
- [x] **AI framework** (`src/enemies/`): `Enemy` base (movement physics, hits, stagger,
      knockback, leash, spawn rise, death dissolve), `Perception` (view cone, hearing
      radius, line-of-sight sweeps, awareness that fills faster up close, forgetting),
      per-enemy state machines, shared `AttackTokens` (max 2 melee + 2 ranged attackers,
      0.35 s between attack starts), ground `Telegraphs` and scheduled light strikes
- [x] **Moving body colliders:** `ColliderWorld.addBody` — enemies block the player and each
      other; spell geometry sweeps still ignore bodies. Sparring constructs migrated too
- [x] **Shadow Knight:** duels at 3–5 m behind a tower shield. Frontal blows through the
      guard deal 20% and drain *poise*; heavy/plunge/riposte break it. Glowing back rune
      takes ×1.5. Cleave → backhand chain, a slow **Doom Descent** (parry bait, 1.05 s
      tell) and a gap-closing lunge. A parry staggers it 2.1 s and exposes it (×1.6).
      Light hits don't interrupt its swings; heavy ones and spells do. Spells pierce the shield
- [x] **Sunkeeper Wizard:** holds 10–24 m, blinks to perches or open ground when the
      player closes to 6.5 m. **Sun Orb** (homing; dodge through or parry to reflect for
      34), **Solar Lance** (marks the ground, strikes 1.15 s later), **Blinding Flash**
      (whites out a player looking at it; look away or break LOS). Any solid hit interrupts a cast
- [x] **Encounters:** data-driven trigger circles with waves, perches and rewards. Title
      card on start and clear; death or fleeing resets them. Three in The Threshold:
      *The Bridge Warden*, *Graveyard Vigil* (guards the Violet Well page), *Sunkeeper Watch*
      (new pillar ruin north of the castle, climbable steps)
- [x] World-space HP bars plus a target frame (name, Vigour, knight poise, text cues)
- [x] Pixel death dissolve: Bayer-dithered, world-noise discard shader on every enemy material
- [x] Felling enemies pays Momentum; clearing an encounter restores Vigour and Momentum
- [x] `npm run enemytest`: 26 deterministic checks via `Game.step()`; Linux-ready tooling

**Notes for Job 6:**
- Levels expose `encounters?: EncounterDef[]`; the `EnemyDirector` reads them once at
  construction. Streaming biomes will need `director.clear()` plus a way to add/remove
  encounter defs as chunks load (key them by id; `Encounter` state can persist per id).
- Enemies walk on `heightAt` plus colliders and treat terrain below 0.15 m as water.
  New biomes with different water levels must pass that through (currently hard-coded).
- `Game.step(seconds)` + `game.manual = true` gives deterministic tests; prefer it over
  real-time key presses for new suites. `render=0` skips drawing in logic suites.
- Enemy count is small by design (≤ ~8 live). Each knight is ~18 meshes, wizard ~11,
  drawn once per depth band.
